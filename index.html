01 / 03

ChatApp architecture

One plaintext round trip: the browser encrypts before it ever calls socket.emit, and app.py never calls anything that would decrypt it — crypto_utils.py is wired only to /generate-key, not to the message path.

02 / 03

Router / room topology

ChatApp has no network router — the server's active_users and chat_rooms dicts do the routing. send_message broadcasts to everyone whose room matches (amber). send_dm ignores rooms entirely and targets one socket id (rose) — it's a second, exceptional path that cuts straight through the broadcast tree.

03 / 03

Direct-message flow

handle_direct_message in app.py always echoes the DM back to the sender's own socket for confirmation, but only forwards it to the recipient if that username is still found in active_users for the same room — an offline recipient silently drops the message, and the sender is never told.
